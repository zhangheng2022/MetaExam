# 未完成首次安装的覆盖修复

2026-11-27，客户 0.1.13，供应方保持 0.1.6，数据库 V10。此前故障记录与旧包见 [Server 2025 安装故障](server2025-installation-fix.md)，保留历史结论。

## 问题和行为

0.1.7 首次安装失败后已有 installation.json，但状态仍是 configuring，缺少完成安装的版本信息。旧入口将其当作正常升级，因此 0.1.9 报 UPGRADE_OWNERSHIP。现在区分已安装升级和未完成首次安装修复，用户可退出管理器后在原目录运行修复安装包（0.1.17 起须从系统托盘选择“退出管理器”），无需更换虚拟机或删除数据。

- 先核对安装记录、数据根 ACL、现有服务路径及虚拟账户、运行库与迁移清单；仅接管本产品明确拥有的未完成安装。缺少配置或 DPAPI 凭据、路径重解析、跨卷程序/数据目录、陌生服务、维护冲突均拒绝。
- 设置业务阻断、禁用服务自动重启并停止服务；保存旧程序与数据冷副本，校验摘要后才替换程序。不会覆盖已有配置、数据库口令、公钥、授权、附件或业务密码。
- PostgreSQL 数据目录有 PG_VERSION 时不再 initdb；初建过程中缺少应用角色/数据库可继续创建，已有角色密码和数据库不变。部分 initdb 目录、错误所有者及权限异常不自动清空或放宽。
- 已完成业务初始化时跳过令牌签发，不重开初始化；未初始化时签发受 ACL 保护的一次性令牌。管理员权限在读取私有配置前检查。
- 验证三项服务、API 版本、schema 和新的 Worker 心跳后才标记 installed、解除阻断。失败返回非零，保留恢复记录和副本，仅允许相同 buildId 续修复；禁止通过删除 pending 文件强行启动。

## 独立环境发现的停服问题

0.1.11 在原 0.1.7 无数据库现场完成修复，但在 0.1.8 已有数据库现场停服时安全退出 10。旧 XML 的通用 arguments 被 WinSW 2.14.0 追加到 pg_ctl 的 stoparguments，停止进程报错退出，包装器仍等待数据库退出。该版本自定义停止的 OnShutdown 分支还会在系统关机时调用不适用的 RequestAdditionalTime。源码依据：[锁定版本 WrapperService](https://github.com/winsw/winsw/blob/v2.14.0/src/WinSW/WrapperService.cs)。

0.1.12 使用仅启动的 startarguments，去除自定义 stoparguments，由 WinSW 先向监督进程发送 Ctrl+C，监督进程运行固定 pg_ctl fast stop 并等待数据库正常退出；真实停库失败不作为备份成功。首次安装与升级共用服务配置生成器，正常升级同步刷新 XML。修复旧现场时，在 API/Worker 停止后显式正常停止旧数据库，兼容旧服务内存中已加载的错误参数。服务事件源由提升权限安装器按 WinSW 官方安装行为注册到 Application，不授予服务账户读取 Security 日志或创建事件源的权限；[官方安装实现](https://github.com/winsw/winsw/blob/v2.14.0/src/WinSW/Program.cs)。Node、PostgreSQL、WinSW 版本均不变。

已安装版本的在线升级保持 PostgreSQL 运行，正在运行的旧包装器不会重新加载 XML。首次从旧版本升级后，需在无考试的维护窗口停止 API/Worker，用固定安装目录的 pg_ctl 正常停库，确认服务停止后重新启动三项服务，使新监督进程与 XML 生效。本次原机已完成该步骤，并通过新配置的 SCM 停服/启动和系统重启检查；未完成首次安装的修复流程会自动停库并启动新配置。

0.1.10、0.1.11、0.1.12 为本次排障中间产物，保留原 EXE 与摘要，不作为最终修复交付。0.1.8 副本在手动正常停库后，使用相同 0.1.11 包续跑成功。另一个原始快照副本使用 0.1.12 自动修复成功，但停服日志暴露控制台信号影响数据库子进程；0.1.11 → 0.1.12 正常升级还暴露旧 API 自动重启的时序问题，保留维护状态后使用同包续跑成功。上述结果作为故障历史保留。

0.1.13 进一步隔离 PostgreSQL 子进程控制台，避免服务停止信号同时影响数据库后台进程，依据 [Node.js 24 子进程文档](https://github.com/nodejs/node/blob/v24.x/doc/api/child_process.md#optionsdetached)。使用实际生产启动函数和 WinSW 停止函数检查监督进程退出 0、干净停库及无异常停库日志。正常升级在替换程序前禁用 API/Worker 自动启动和失败重启，启动新程序时恢复，避免旧 API 被 SCM 恢复动作重新拉起。

安装器不修改 Windows Administrator 密码，也不会把已有 MetaExam 业务管理员密码改成默认密码。
