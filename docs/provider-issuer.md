# 供应方离线授权签发器

独立的 Windows 单人桌面工具。供应方数据存于当前 Windows 用户的 `AppData/Roaming/MetaExam.Issuer`；客户业务数据库、管理器与服务不参与签发。客户程序版本 0.1.3，签发器独立版本 0.1.2。两种 EXE 均为未正式签名的内部交付。

## 日常使用

1. 打开签发器，首次设置 12～128 字符密钥库口令。不会自动生成任何签名密钥。
2. 在“密钥与客户包”明确选择测试或正式环境，创建密钥。接续原 0.1.2 测试客户时，显式导入原 `internal-test` 私钥及匹配公钥，不能重新生成替代密钥。
3. 导出公钥及目标版本的信任清单，交给客户包构建流程。签发前导入对应客户包的信任清单。原 0.1.2 可通过专用入口读取真实 `public-keys.json` 建立测试配置；不要凭空填写不受客户信任的公钥。
4. 在“客户与实例”保存客户编号、名称，选择客户并导入 `.mreq`。同一实例不允许换客户或设备哈希。申请不证明付款或身份，需人工核对。
5. 核对历史序号：新实例确认从未签发；已有实例导入历史 `.mlic` 或填写有依据的最高序号。申请本身不带最高序号，不能当作零。
6. 新建授权，选择申请、密钥和目标客户包，输入人数及期限。界面日期按北京时间，文件 UTC；到期时刻不包含在有效期中。永久授权必须显式选择；未来生效的文件需到生效后才可导入。
7. 预览核对客户、实例、序号、人数和期限差异后确认签发。记录提交后才能导出；取消或导出失败不撤销已签发记录，稍后到“签发记录”重新导出。
8. 续期／扩容从记录复制草稿，重新选择客户包与期限，分配更高序号。历史授权不可修改；重新导出始终保留同一字节和摘要。

`reports.basic` 为历史兼容字段；当前客户统计功能不单独按此标记限制，工具不提供虚假收费开关。默认功能包含 `exam.core`；人数为同时作答容量，不等于账号数。

## 密钥和恢复

使用 scrypt（N=32768、r=8、p=1）与 AES-256-GCM 加密密钥库及备份。私钥只在独立 Node 子进程内解密；口令不进入命令行、环境变量或日志。10 分钟无操作、锁屏、休眠或手动锁定时终止签发子进程。忘记口令无法恢复；停用密钥只阻止后续签发，不远程撤销已交付授权。

台账中的客户名称、申请和授权记录为本机 SQLite 普通数据，私钥单独加密；完整导出备份使用独立备份口令加密。备份为一致性逻辑快照，不依赖复制正在写入的 SQLite 文件。备份最大明文 64 MiB。

恢复先解密、验证签名、实例关联和数据库约束，保存当前台账的加密恢复前快照，再在事务中合并。不同已使用台账不可混合；空台账可接管备份。同台账保留已有较高序号和较新签发记录，密钥停用状态不回退，失败回滚。恢复前快照位于用户数据目录，使用本次备份口令保护。

恢复后全部实例须重新核对序号，并填写完成核对说明才能继续签发。离线旧备份无法证明备份后未对外签发；应补录最新授权或提高序号下限。工具不支持多台电脑同时签发，不提供在线同步或远程吊销。

## 开发和构建

通过根目录 `tools/run.ps1` 执行：

- `dev:issuer`：构建并启动独立签发器，不启动客户后台。
- `test:issuer`：隔离台账、真实 Electron、客户导入和公钥构建检查。
- `package:issuer`：生成供应方 EXE；包内无真实私钥、台账、PostgreSQL 或 WinSW。
- `test:issuer:package`：运行实际打包程序的 Electron 回归。
- `package:win`：明确测试信任配置的客户内部包，可沿用 `.local/provider/public-keys.json`。
- `package:win:production`：正式授权信任配置的客户内部包；必须设置 `METAEXAM_TRUST_MANIFEST` 为签发器导出的目标版本清单，缺失时禁止回退测试密钥。实际发布前还需独立验收和程序签名安排。

指定信任清单的公钥必须为 Ed25519，指纹须匹配，环境与目标版本一致。客户载荷含 `public-keys.json` 和 `trust-manifest.json`；只有公钥，不能包含签发服务或私钥。更换密钥需要受控更新客户信任配置，本批不自动把旧测试安装转换为正式配置，原升级流程仍保留客户已有信任配置。

不覆盖已有同版本 EXE；客户旧包保留。供应方卸载只删除程序，用户台账保留。生产实际密钥仅由操作者生成，自动化测试全部使用临时密钥，不交付测试私钥。
