# M2 第四批：考试发布与考生名单

日期：2026-11-25。交付“选择冻结试卷 → 安排北京时间 → 按班级生成名单 → 核对并发布 → 学生查看本人安排 → 开考前取消”。数据库 V8。本批不开放实际入场、在线答题、自动提交、阅卷、成绩、名单 Excel 导出或单独增删考生。未激活仍可管理草稿；发布需有效本地考试授权。

## 启动与人工验收

开发库已备份并升级 V8。重新运行 `./tools/run.ps1 dev`。管理员可管理全部考试；教师仅管理本人且所有所选班级仍有有效授课关系的考试。

1. 准备启用的课程、班级、学生、授课关系和同课程冻结试卷。教师需使用本人冻结的试卷，管理员可使用任意冻结试卷。没有冻结试卷时先在“试卷管理”完成冻结。
2. 进入“考试管理”，点击“创建考试”。填写考试名称、课程、冻结试卷、参加班级、开始／结束时间和答题时长。时间按北京时间填写，不取浏览器所在时区。试卷选项附版本短号以区分同名试卷。
3. 保存后查看名单。只纳入所选班级中启用且具有学生角色的账号，同一学生跨班自动去重；处于首次强制改密的学生也可列入，但须先改密才能进入业务页面。
4. 在班级中添加／移除学生或修改学生姓名，再尝试发布，应提示名单变化。点击“编辑与刷新名单”重新保存，查看新名单后再发布。班级／课程停用或授课关系撤销也会阻止写入。
5. 未激活时发布应被拒绝，草稿仍保留。通过既有本机维护授权命令导入有效测试授权后重试；不开放匿名网页授权导入。授权须包含 exam.core，且在开考时间仍有效。
6. 发布前二次确认试卷及人数。发布成功后试卷版本、时间和名单只读，刷新／重启仍保留。继续修改源题、复制试卷或调整班级成员，不应改变该考试的固定版本和名单。
7. 学生登录“我的考试”只能看到本人被列入且已发布／取消的考试，不能看草稿、试题、答案、冻结版本 ID 或其他考生。取消前可看到待开考安排；答题入口明确尚未开放。
8. 开考前点击“取消考试”，填写原因。学生应看到取消状态和原因；不能恢复该考试，需要重新创建。开考时间到达后取消请求被拒绝，本批不提供强制停考。
9. 检查第二教师无法读取他人考试，学生直接访问管理路由被拒绝。刷新时断连应显示重试并收起旧详情，恢复后可重新读取。手机端导航可用，列表在表格内部横向滚动。

## 时间、名单与状态规则

- 一场最多 50 个班级、5000 名去重考生；本批以班级全体启用学生为名单来源，不支持任意指定用户 ID、手工剔除或发布后补录。
- 答题时长 1～480 分钟；考试窗口至少覆盖答题时长、最长 7 天。草稿可以保存已过去的时间，但发布时开始时间必须晚于服务器当前时间。
- 数据库存 timestamptz，界面统一北京时间。状态在读取时按服务器时间派生：开始前“待开考”、开始至结束前“考试时间内”、到达结束“已结束”。不依赖定时任务；页面通过刷新更新。此状态只表示时间窗口，不表示已有考生答题。
- 答题阶段的预定截止规则为 `min(实际入场时间 + 答题时长, 考试结束时间)`；本批仅保存参数和展示说明，不创建答题记录。
- 创建／编辑草稿会原子重建名单。发布前比较当前符合条件的用户 ID、用户名和姓名与已保存名单；不同即要求重新确认。班级名称在保存时快照，发布后的姓名／班级名称不随组织改名更新。
- 教师需要所选全部班级当前启用、课程启用、本人对应课程授课关系有效；跨班权限不会从“同课程任教”自动扩大。撤销关系后教师失去该考试管理访问，管理员仍可处理。
- 取消只允许已发布、尚未到开始时间的考试，必须填写原因；不能删除或恢复。重复发布／重复取消幂等返回原考试，其他过期编辑通过 revision 返回冲突。

## 本地授权边界

发布与草稿维护不同：事务内先取得既有业务咨询锁、检查时间和名单，再在同一连接锁定 license_state。读取本地可信公钥，复核签名、设备／安装实例、版本、序号与时间高水位；需要 exam.core。数据库或文件读取故障不当成退出登录、不回退内存授权，也不会继续发布。验签没有在线授权、远程公钥或在线时间服务。

授权到期时间必须严格晚于开考时间；允许在考试窗口内到期，**这不承诺到期后仍能新入场**。发布记录保存授权 ID、序号、到期时间和同时答题上限供维护追踪，学生接口不返回这些字段。

名单人数不等于同时答题人数：即使名单超过授权并发上限也可发布。本批不占用名额，不保证未来一定能入场；后续入场须再次验签并在数据库事务中分配名额。有效入场后中途到期继续作答的规则仍只在 domain 中定义，不能用考试发布记录替代可信入场授权。

V1～V7 SQL 和校验和保持不变；V8 新增 exams、exam_classes、exam_roster，新增 exams.manage（管理员／教师）和 exams.self（学生）权限。Drizzle 声明同步维护，禁止 push。API／Worker 不自动迁移。

考试引用 paper_versions 的固定 ID；名单保存用户 ID、用户名和姓名快照，核心关联有外键。发布、取消、名单重建与审计在事务内完成；统一业务写锁串行化角色／授课／成员变更和发布，草稿 revision 防止丢失更新。数据库触发器保护已发布考试配置和名单，允许的唯一变更是开考前取消及其元数据。运行角色具有必要 DML，无 DDL；发布失败回滚数据库状态，文件时间高水位可能保守前移，不回退以绕过授权。

## 接口

管理前缀 `/api/v1/exams`，要求 Cookie 会话、相应角色与 exams.manage；强制改密账号不能访问。写请求沿用 CSRF、严格 Zod 校验和统一错误 `{code,message,requestId}`。学生接口独立挑选响应字段。

| 方法与路径                   | 用途                                                     |
| ---------------------------- | -------------------------------------------------------- |
| GET `/exams`                 | 管理范围内名称／状态筛选分页                             |
| GET `/exams/choices/papers`  | 当前可选冻结试卷，按课程／名称分页                       |
| GET `/exams/choices/classes` | 指定课程的有效授课班级，搜索分页                         |
| POST `/exams`                | 新建草稿并生成名单，201                                  |
| GET `/exams/:id`             | 管理详情、固定版本和发布时授权摘要                       |
| GET `/exams/:id/roster`      | 用户名／姓名筛选的考生快照分页                           |
| PATCH `/exams/:id`           | revision、草稿配置与班级名单整体更新                     |
| POST `/exams/:id/publish`    | 本地验签后发布，200；重复请求幂等                        |
| POST `/exams/:id/cancel`     | revision 和 reason，开考前取消，200                      |
| GET `/my-exams`              | 学生本人已发布／取消安排分页；无答案、名单或内部授权字段 |
