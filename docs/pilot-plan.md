## 执行顺序

1. 固定试点基线和验收清单。
2. 账号与班级成员 Excel 导入：预检、逐行报告、显式确认、事务复核、原子写入和重复确认。
3. 考中状态：未入场／作答中／已交卷、最近成功保存、交卷方式、筛选与刷新。没有心跳不展示在线人数。
4. 30／100／300 人分档负载：登录、入场、持续保存、交卷、判分及进程故障恢复；报告实测环境和延迟，不作为生产容量承诺。
5. 新版本签名包、真实旧包升级及独立环境试点。

## 0.1.22 实现与操作

数据库保持 V10，Node／PostgreSQL／WinSW 和供应方版本不变，无新增依赖或历史迁移修改。

管理员先创建班级，再到“账号管理 → 批量导入”下载模板。工作表“账号”的五列固定为用户名、姓名、角色、班级编码、初始密码；角色填写学生或教师，教师班级留空。所有单元格为文本，保留用户名的前导零；每文件最多 500 行、2 MiB，不接受公式、链接、合并、隐藏行和非文本单元格。新增账号填写各自密码，已有账号密码留空、姓名／角色须匹配且账号启用；已有成员跳过，文件内同名账号报错，不隐式修改原账号。

上传仅预检，表格保留源行号并展示逐行问题，存在错误整批不能确认。校验通过后使用既有 PasswordService 分批哈希，预检只在有界内存保存 10 分钟，不保存 Excel 或密码原文，不向页面返回密码哈希。最多同时两个文件处理、每账号一个操作、八份有效预检；新成功预检替换本人旧预检。服务重启、取消和超时后重新上传。

确认在统一管理咨询锁和同一数据库事务内重新验证管理员权限、账号／班级／成员状态和 revision，状态变化要求重新预检。整批成功后写入仅含数量的审计回执；重复确认同一 ID 返回原结果，通信异常时可重试确认。若已经离开页面，先查看账号与成员是否已创建，不能通过重置密码或删除账号“重试”。预检及确认不改变身份会话、授权、考试固定名单或历史成绩。

教师或管理员在已发布考试详情查看“考中状态”，手动刷新。人数按发布固定名单汇总；筛选只影响名单表格。显示未入场、作答中、到期待收卷、已交卷，以及最近成功保存、交卷时间与方式。没有保存显示“—”；最近保存不是在线状态。失败清除旧名单并显示错误，不能误报零人数。接口复用考试所有权和有效授课范围，不返回题干、作答、答案、分数或内部授权信息。

新增命令：`./tools/run.ps1 test:pilot`（隔离库、受限数据库身份、真实浏览器）；`./tools/run.ps1 test:pilot-load`（30／100／300 人短时负载）。可用测试环境变量 `METAEXAM_PILOT_SIZE=30` 单独复验某档；它只被测试脚本读取。

30 人额外中断仅属于该隔离库的临时运行身份：禁止连接并终止已有连接，接口返回 503；恢复连接后 revision=7 保留，后续保存、交卷与判分完成。没有停止共享开发 PostgreSQL，不能把该测试写成真实数据库服务重启验收。

初始同进程客户端／API 压测在 300 人集中入场时发生连接拒绝；失败日志保留。将负载客户端与 API 拆成独立进程后，30／100／300 人全部通过；此调整只修改测试驱动，不通过放宽产品权限、容量或失败断言获取通过。原始结果和截图位于忽略提交的 `artifacts/pilot/`，包括 `load-results-all.json` 与单独连接中断复验结果。
