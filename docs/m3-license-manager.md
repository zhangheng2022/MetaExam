# M3 第一批：本地管理器授权申请与导入

日期：2026-11-26。交付“导出申请 → 选择授权文件 → 本地预检 → 核对变更 → 确认导入 → 刷新状态”。沿用 V10，无数据库迁移，不改变考试发布、入场容量或合法入场后续答的规则。

## 使用流程

1. 以 Windows 管理员身份启动本地管理器；普通权限点击授权操作时提示重新提升权限，不自动提权、不放宽 ACL。
2. 在软件授权卡片点击“导出授权申请”，选择 `.mreq` 保存位置。申请包含现有协议中的安装实例、设备哈希、指纹模式和程序版本，不含原始硬件序列或私钥。取消不生成文件，已存在的文件不覆盖，请另选文件名。
3. 获得供应方签发的 `.mlic` 文件后，点击“导入授权文件”。本机检查可信公钥、Ed25519 签名、产品、版本、安装实例、设备、序号、有效期和权益。只读取不超过 64 KiB 的 UTF-8 普通文件。
4. 确认弹窗展示当前与新授权的期限、同时作答人数、功能，以及新授权生效时间、编号、序号。未激活时当前权益显示“—”。只有预检成功才显示确认按钮；取消不导入。
5. 点击“确认导入”。预览在主进程保留 10 分钟，确认导入已预览的同一份内容，源文件后续修改不会悄悄改变导入内容。确认时复核权限并重新验签；当前授权已被其他操作更新时要求重新预检。
6. 导入成功立即重新读取状态；如果恰好存在导入前发起的状态检查，等待其完成后再读取，避免旧检查覆盖新授权。窗口重开后继续从数据库本地验签。

导入失败后需重新选择文件。格式、签名、设备、序号、期限等验证失败保留当前授权。通信中断、超时或提交后的水位文件写入异常可能无法确认最终结果，此时明确提示检查授权状态，不承诺数据库一定没有提交。

## 实现边界

- Electron 仅新增 request、preview、confirm、cancel 四个明确 IPC，全部复用主 frame 与本地页面来源校验。原生选择器返回的路径仅用于主进程；renderer 不提供路径、不获取配置、原文、签名、公钥或设备信息。
- 主进程先检查 Windows 管理员身份，再调用固定路径的项目／安装包 Node 和维护 CLI。`license-desktop` 在加载配置前再次校验权限，参数通过有大小限制的 stdin JSON 传输，不写临时授权文件或命令行原文。错误仅返回白名单代码，不输出底层配置和原文。
- 维护 CLI 复用运行数据库身份，无所有者凭据、DDL 权限或新增 HTTP 接口。授权仍使用已有可信公钥文件与 Node crypto，验签不请求授权服务器、公钥或在线时间。
- 预览在同一事务读取当前授权摘要与比较信息，不改变授权内容。确认在 license_state 行锁内比较摘要、重新本地验签并写入已有 license_history/state，避免多窗口覆盖。Windows 指纹在取锁之前采集。
- 预览 ID 不能直接充当授权凭据；新选择、取消、确认、页面重新加载或窗口关闭使旧预览失效。主进程串行处理操作，确认失败也消费该预览；重复导入同一合法文件仍按既有幂等规则处理。
- 不改变当前考试名额、已保存答卷或可信入场记录；已合法入场后当前授权到期不阻止续答，新入场仍按最新授权原子校验容量。
- 本阶段不加入授权签发 UI、在线激活、备份恢复、服务启停或升级入口。

原生对话框及 IPC 边界参考 [Electron dialog](https://www.electronjs.org/docs/latest/api/dialog) 和 [Electron 安全指引](https://www.electronjs.org/docs/latest/tutorial/security)；组件 API 使用本项目锁定的 Ant Design 6.7.2 CLI 查询，视觉沿用 DESIGN.md 默认蓝色规则。

## 验证

`test:license-manager` 使用独立测试库和临时 Ed25519 密钥，私钥只存在测试内存：

- 真实运行数据库权限可预览／导入，但不能建表；申请导出、不覆盖文件、取消选择、取消确认、10 分钟过期、重复确认、权限拒绝、64 KiB 限制、源文件替换、并发授权更新、幂等历史记录。
- 签名、公钥、产品、设备、实例、版本、期限和序号异常均不覆盖当前授权；预检后到期或撤销公钥在确认时仍被拒绝；CLI 新进程重新验签保持授权状态。
- 真实 Electron 先验证普通权限拒绝与外部窗口对全部新 IPC 的调用被拒绝，再注入仅测试进程使用的权限和选择器适配器，连接真实文件、数据库与验签逻辑验证界面。生产没有测试权限环境变量或隐藏入口。
- 覆盖预览与取消、成功导入、旧状态请求与导入交错、重新打开页面、错误设备、并发更新要求重新预检、窄窗口；截图与结果在忽略提交的 `artifacts/license-manager`。

本机测试不会提升权限或关闭整机网络。原有单元测试在禁止 TCP/fetch 的进程中验证纯本地签名；数据库集成测试必须使用本机回环连接。模拟权限和选择器不代表真实提升权限、原生对话框交互或安装 ACL 验收。

本次 build、typecheck、lint、format:check、27 项单元测试、test:license-manager、test:desktop、test:ui、test:integration、test:attempts、package:win 和 test:package 均通过。答题回归涵盖合法入场后授权到期续答、容量限制、30 个并发入场请求、真实 Worker 到期收卷及浏览器保存／刷新／断连恢复；不代表大规模生产负载验收。

## 独立环境待验收

1. 新内部包净机断网安装；普通用户不能操作受限配置，授权操作有明确权限提示。
2. 提升权限启动客户端，用真实原生对话框导出申请、预览和导入测试授权。验证取消、保存文件已存在、目录无写入权限、错误设备、篡改和旧序号。
3. 两个提升权限客户端同时预览不同授权；一个导入后，另一个旧预览必须失败并要求重新预检。
4. 在实际服务身份运行 API/Worker，确认导入后状态更新、系统重启后重新验签；HTTP 开发与 HTTPS 安装的业务登录入口不受影响。
5. 新授权容量变化只影响后续入场判定；已合法入场的考生仍按既有权限、截止时间和交卷规则作答。
6. Windows 125%／150% DPI 和窄窗口检查授权弹窗。内部包未正式签名；开发机普通进程验证不替代上述检查。
