日期：2026-11-25。范围为真实账号管理、教学组织维护、角色工作台和审计查询；不包含 Excel 导入、自定义角色编辑器、管理员忘记密码恢复、题库、组卷或考试。

2026-11-27 后续调整：账号密码下限由 12 个字符改为 6 个字符，允许纯数字；原有账号密码、强制改密和会话撤销规则保留。供应方密钥库口令不受此次调整影响。

## 启动与迁移

```powershell
./tools/run.ps1 build
./tools/run.ps1 db:start
./tools/run.ps1 db:migrate
./tools/run.ps1 dev
```

浏览器访问 http://127.0.0.1:5173/login。管理员可从导航进入账号、班级、课程、授课安排及操作日志。教师与学生改密完成后登录进入工作台，也可查看个人信息。

V1～V3 SQL 保持不变，V4 增加管理权限、revision、强制改密标记及审计目标/详情。现有账号默认不强制改密；新建和重置账号必须改密。API/Worker 不自动迁移。

本次本机升级前使用 pg_dump 备份到 `.local/backups/m1-before-v4-1795602381333.dump`，升级后原账号、任务、授权历史数量保持不变，ready 为 true。业务测试均使用随机命名的独立测试库，不创建开发演示账号。

已有安装版须先备份数据库及配置、公钥和安装记录，停止 API/Worker，部署匹配的新程序后，在管理员终端执行：

```powershell
$env:METAEXAM_CONFIG = 'C:\ProgramData\MetaExam\config.json'
& 'C:\Program Files\MetaExam\runtime\node.exe' 'C:\Program Files\MetaExam\server\cli.cjs' migrate-installed
```

随后启动服务并检查 `/health/ready` 返回 schemaVersion=4。运行角色只获得业务 DML 权限，不获得 DDL；迁移失败须停止升级、使用匹配旧程序和已验证备份恢复，不能删除迁移记录或重新 initdb。安装器仍拒绝覆盖安装，不提供一键升级。

## 业务边界

- 账号用户名创建后不变，姓名可改；管理员/教师/学生可多选。账号、班级、课程采用启停，不提供物理删除。
- 临时密码由管理员设置，6～128 字符，允许纯数字，无字母或符号组合要求，不统一生成默认密码、不自动发送。管理员不能重置自己，应使用验证原密码的改密入口。
- 强制改密账号可访问本人身份、改密及退出；管理概览、管理接口和教学信息均被服务端拒绝。成功改密撤销所有会话，重新登录。
- 停用撤销会话，角色调整在后续服务端认证生效。不能停用自己或移除最后一个启用管理员；并发管理写操作在同一数据库咨询锁下串行检查。
- 有学生归属或授课关系时不能移除对应角色。停用保留历史，禁止新增分配；关系解除不删除人员或组织。
- 学生可加入多个班级；授课关系绑定教师、课程、班级。重复添加/移除幂等。关系与角色变更共享事务锁，避免并发产生无效关系。
- 编辑与重置使用 revision；冲突返回 409，必须重新加载。用户名/编码冲突明确返回 409。
- 教师和学生的信息由服务器根据当前登录身份查询，客户端账号参数不会改变范围；学生不能读取班级学生名单。
- 写操作与成功审计在同一事务提交；业务校验失败记录事件、操作人、结果和请求编号。成功记录增加目标及必要变更内容；不记录密码、密码摘要或 Cookie。

## 接口

| 接口                                                  | 用途                                          |
| ----------------------------------------------------- | --------------------------------------------- |
| GET/POST `/api/v1/admin/users`                        | 分页筛选/创建账号                             |
| PATCH `/api/v1/admin/users/:id`                       | 修改姓名、角色与启停状态                      |
| POST `/api/v1/admin/users/:id/reset-password`         | 重置临时密码，撤销会话                        |
| GET/POST `/api/v1/admin/organizations/:kind`          | 班级或课程列表/创建，kind 仅 classes、courses |
| GET/PATCH `/api/v1/admin/organizations/:kind/:id`     | 详情/编辑                                     |
| GET/POST `/api/v1/admin/classes/:id/members`          | 学生名单/加入学生                             |
| DELETE `/api/v1/admin/classes/:id/members/:studentId` | 移出学生                                      |
| GET/POST/DELETE `/api/v1/admin/assignments`           | 分页查询、添加、解除授课关系                  |
| GET `/api/v1/admin/audit-events`                      | 按关键词、结果和起止时间查询日志              |
| GET `/api/v1/teaching/me`                             | 本人班级及课程/授课信息                       |

管理接口要求相应权限及管理员角色。列表返回 items、total、page、pageSize，最多每页 100 条；学生和授课选择使用分页搜索。管理页面同源提供，刷新深层路由仍可进入应用。

## 验收流程

1. 管理员创建一位教师、两位学生；首次登录必须先改密，刷新或直接访问管理地址不能跳过。
2. 创建班级与课程，将学生加入班级，再分配教师授课。重复提交不增加重复关系。
3. 教师与学生查看自己的工作台；另一名未分配学生不能通过请求参数查看他人关系。
4. 编辑姓名与角色，测试停用、重置密码、移除已有关系的角色、最后管理员和两个窗口编辑冲突。
5. 查询操作日志，确认目标、结果与北京时间正确，详情没有密码或令牌。
6. 重启 API 后确认数据和有效会话保留，原授权与任务闭环继续可用。

自动检查：`test:management`（管理接口及浏览器流程）、`test:m1`、`test`、`test:integration`、`test:ui`；打包后执行 `test:package`。浏览器流程通过真实 UI 创建账号、班级、课程、入班、授课，验证日志、强制改密、学生工作台和无权限页。截图及结果位于 `artifacts/m1-management`，测试账号随独立库清理。
