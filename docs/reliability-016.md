# 0.1.16 现有功能可靠性修复

本批不新增业务功能、API、数据库 schema 或迁移；客户版本 0.1.16，供应方保持 0.1.6，锁定依赖和历史安装包不变。

## 修复范围

- 答题页在未保存或保存中拦截站内离开、浏览器前后退。取消离开保留输入，保存中禁止放弃。新增真实浏览器断网保存失败后的返回/后退回归。
- 首次安装与修复共用健康判断：API 当前版本、schema、Worker 新心跳及三项运行服务全部通过才提交 installed。失败保留 configuring 或 pending，以原包继续修复。
- 卸载先保存受保护的原版本清单、原授权公钥及已有 LAN 防火墙范围，停止并移除服务后标记 uninstalled。重装验证同一目录、相同 Node/PostgreSQL/WinSW、相同迁移集合、禁止降级；先备份保留数据，再恢复程序和服务，不重新生成密码、公钥或初始化已有数据库。备份、替换和启动中断允许相同 buildId 续跑。旧卸载器已删除且没有备份的公钥不能自动恢复，不用新包的测试公钥替代。
- 升级的备份/迁移阶段保持 PostgreSQL 运行；启动阶段关闭维护数据库连接、禁用旧 PostgreSQL 自动恢复、正常停库、刷新服务配置并启动新监督进程，再重新取得数据库锁。数据库重启期间保留 maintenance 标记以排斥备份/恢复，重新取得数据库维护锁后才移除；整个过程保留安装文件互斥锁和 pending，只有所有健康检查通过才放行业务。同包可恢复停库后的中断。
- Release 草稿短暂不可见时有界重试；空值返回明确错误。发布检查加入真实旧载荷升级、安装修复和答题回归，缺失旧载荷必须失败。

历史 0.1.13 的人工 PostgreSQL 停库说明及验收结果保留于 [首次安装修复](install-repair.md)；本批从升级程序内部完成该步骤。
