# M2 第六批：阅卷与成绩发布

日期：2026-11-25。交付“已交卷答卷 → Worker 客观题判分 → 教师评阅简答 → 考试结束后确认发布 → 学生查看本人成绩”。数据库 V10。保留上一批答题与本地授权语义；评分／查分不再次要求软件授权有效。本批不实现成绩统计导出、排名、及格线、双评仲裁、发布后复核改分／撤回、学生标准答案查看、补考或延时。

## 评分规则 v1

| 题型 | 评分规则                                                                         |
| ---- | -------------------------------------------------------------------------------- |
| 单选 | 选项 UUID 等于冻结版本的唯一答案，得本题满分，否则零分                           |
| 多选 | 选项集合完全相同，顺序无关；漏选、多选或错选均零分，不设部分分                   |
| 判断 | 布尔值完全相同得分；选择“错误”与未作答不同                                       |
| 填空 | 每空命中该空任一候选答案且所有空都正确，整题满分，否则零分；按稳定空位 UUID 匹配 |
| 简答 | 保持待评，教师手动给 0～本题满分，步长 0.5；即使未作答也需确认零分               |

填空严格沿用冻结题目中的 caseSensitive 和 trimWhitespace；后者只处理首尾空白，大小写忽略采用 Unicode 小写转换。不做模糊匹配、全半角转换、数学等价或主观语义推断。未作答的客观题零分。评分以半分整数单位持久化和汇总，不产生浮点分摊误差。规则版本保存为 1，后续改变规则必须设计明确的新版本及历史成绩处理，不能自动覆盖已有成绩。

## 人工验收

1. 运行 `./tools/run.ps1 dev`，按 [答题会话验收](m2-attempts.md) 准备已发布考试和学生答卷，保持 Worker 运行。本机不创建演示账号、不修改考试时间来绕过开考规则。
2. 学生交卷后，教师从“考试管理 → 考试详情 → 阅卷与成绩”进入，刷新可见已交卷、待评分、已评完、未入场人数。未计算的客观题在 Worker 恢复后自动补算，不需重新交卷。
3. “查看答卷”逐题检查冻结题目、标准答案、解析、图片与考生答案。验证五种题型，特别是多选漏选、填空候选答案／大小写／空白规则、未作答和判断选“错误”。修改题库当前版本不能影响该冻结试卷的判分依据。
4. 简答题输入分数和公开评语，点击保存。超出满分、负数和非半分步长被拒绝；当前得分“待评”与 0 分明确区分。人工不能修改客观题得分。
5. 未保存评分时切题、关闭抽屉或刷新本题应提示放弃修改；浏览器刷新／关闭有未保存提醒。网络失败保留表单，可重试。两个教师／管理员打开同题，后保存的旧版本被拒绝，需重新读取核对。评语与答案均按纯文本显示。
6. 发布前学生点击“我的考试 → 查看成绩”，只能看到“成绩尚未发布”，不能通过直接 API 请求获取分数或评语。其他教师不能访问他人考试的阅卷和图片；管理员可管理全部，教师被撤销授课后失去访问权。
7. 考试窗口结束、无进行中答卷且全部已交卷答卷都评完后，点击“发布成绩”并二次确认。仍有待评、Worker 尚未处理或考生仍作答时应拒绝发布。发布确认期间有人更新评分，旧整体版本也会被拒绝。
8. 发布成功后显示发布时间。评分和发布记录锁定，不再显示评分输入，不允许撤回／删除／重评。重复发布返回原发布时间，不重复发布。
9. 学生刷新看到本人总分、逐题得分和公开评语，不看到标准答案、解析、完整试题、他人成绩或评分人身份。未入场学生显示“缺考”，不能按零分答卷展示。已经入场但空白交卷的答卷经评分后可以是零分。
10. 刷新页面和重启 API／Worker 后成绩仍保留。临时断连时成绩页显示错误并收起旧结果，恢复后重试。手机端抽屉、表单、题图和成绩列表可读，无整页横向溢出。

关闭页面与离开普通业务路由不承诺保存未提交表单；请等待评分保存成功。系统不保存浏览器离线评分副本。发布后的学生端当前只展示得分与评语，没有查看试题／标准答案入口。

## 数据、并发与权限

V1～V9 SQL 字节与校验和保持不变。V10 新增 exam_grading（规则版本、整体 revision、发布记录）与 attempt_scores（每题分数、评分方式、评分人、评语、revision）。Drizzle 声明同步；只执行显式迁移，不使用 push。评分表不修改 exam_attempts、attempt_answers 或冻结题目。

Worker 每轮处理一份缺少评分的已交卷答卷；整份题目判分、待评行及审计在同一事务内完成，异常全量回滚，重启后自动重试。保存了全部评分行的答卷不重复计算。既有 V9 已交卷答卷在升级后也进入扫描；原有简答需人工评阅。Worker 同时继续任务租约处理及截止收卷，长任务或停机可延后判分，不改变原截止时间。

管理接口复用考试 exams.manage 权限和原有作用域：教师只能访问本人且仍有有效授课关系的考试，管理员可管理全部。管理写入、判分和发布复用业务咨询锁，评分行 revision 防止覆盖、考试整体 revision 防止按旧汇总发布。发布与评分争用同一状态行；数据库触发器二次校验分值上限、题目归属、题型、已交卷条件和发布完整性，并禁止发布后的评分／状态变更及删除。该机制不承诺抵御数据库管理员绕过触发器。

未入场者不阻止考试结束后发布；发布一场全部缺考的考试也是允许的。已入场尚未收卷者阻止发布，即使已经超过时间窗口，也须等待截止收卷完成。学生成绩接口显式选择安全字段，未发布不返回分数、满分或评语；已发布仍不返回题目答案、考生原始作答、评分身份。教师阅卷图片按固定试卷和当前考试权限鉴权，不依赖当前题库访问权限，不开放静态目录。

审计记录自动评分、人工评分和发布的对象、题号、分数与请求标识，不复制题目正文、考生答案或评语。运行数据库角色只有所需 DML，不能 DDL；新表权限由既有安装维护流程同步授予。

## 接口

以下路径统一加 `/api/v1`，使用已有 Cookie 会话、CSRF、严格 Zod 校验与统一错误格式。管理前缀为 `/grading/exams/:id`。

| 方法与路径                                                     | 行为                                               |
| -------------------------------------------------------------- | -------------------------------------------------- |
| GET `/grading/exams/:id`                                       | 考试阅卷汇总、整体版本与发布条件                   |
| GET `/grading/exams/:id/candidates`                            | 考生搜索分页、作答／评分状态、已评完总分           |
| GET `/grading/exams/:id/attempts/:attempt/questions/:position` | 逐题读取已交卷答卷、冻结题目和评分                 |
| PUT 同上                                                       | revision、score、comment，仅简答人工评分           |
| GET `/grading/exams/:id/attempts/:attempt/images/:file`        | 当前考试范围内的冻结题图                           |
| POST `/grading/exams/:id/publish`                              | 校验整体 revision 后发布，幂等返回原发布时间       |
| GET `/my-exams/:id/result`                                     | 仅本人、发布后可见的安全成绩；未发布／缺考独立状态 |
