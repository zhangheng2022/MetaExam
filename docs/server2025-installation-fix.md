# Server 2025 首次安装失败修复

2026-11-27，客户包 0.1.9，供应方仍为 0.1.6，数据库保持 V10。

## 故障与修复

在 Windows Server 2025 Standard Evaluation 桌面体验 x64（26100.32230）的 VirtualBox 独立环境中，客户 0.1.7 完成文件复制后提示 `Service configuration failed`。数据库服务日志显示 `Cannot find module 'pg'`。安装器等待数据库就绪约 90 秒，因此进度条已满但安装没有完成。

- `postgres-service.mjs` 未打包，直接从 `server/db.cjs` 所在目录加载 `pg`。原包只有 API/Worker 中内联的驱动，缺少该独立运行时依赖。现在沿用锁定版本的依赖复制逻辑，交付 `pg` 及其依赖；不改变 Node.js、PostgreSQL 或 WinSW 版本。
- 在干净、断网副本安装中间包 0.1.8 后，PostgreSQL 已初始化并正常运行，但 `setup-token` 报 `MAINTENANCE_REQUIRED`。首次登录令牌写入锁与离线维护锁都使用 `184427`，令牌仓储的第二个连接被自身持有的排他维护锁拒绝。0.1.9 将令牌文件序列化锁改为独立的 `184430`，保留每条运行连接的共享维护锁和全部管理员/ACL 检查。
- 中间包还暴露出 Inno 的文件复制阶段成功后，`ssPostInstall` 抛错仍可能最终返回 0。客户安装器新增共用结果处理逻辑：后置步骤开始时标记失败，全部完成后清除；未完成返回退出码 10。升级与 VC++ 运行库失败同样覆盖。安装界面在该阶段明确显示正在配置服务和初始化数据库。官方接口见 [GetCustomSetupExitCode](https://jrsoftware.org/inno-setup/documentation/topic_scriptevents.htm)。

  0.1.7、0.1.8 EXE 与摘要均保留，不覆盖旧资产，不将失败的首次安装当作正常升级基线。0.1.8 是排障中间包，不能作为可用交付。

## 回归范围

- `test:package` 在工作区外从真实包内解析 `pg` 并连接隔离数据库；新增检查先在 0.1.7 复现缺依赖，再在修复包通过。既有隔离包业务检查及打包 Electron 诊断回归通过。
- `tests/setup.mts` 持有真实令牌文件锁，再通过真实仓储的第二个连接签发一次性令牌，覆盖初始化 HTTP、远程/CSRF 拒绝及重复初始化拒绝。
- `test:installer-result` 编译实际共用 Pascal 实现，执行真实 Inno 静默安装的成功/后置异常路径，分别断言退出码 0/10；该检查纳入客户打包入口，不安装产品服务。
- 本机 build、typecheck、lint、format:check、31 项单元测试、数据库集成、考试进行中拒绝维护、test:desktop、签名检查通过。开发机仍只运行普通进程。
- `test:upgrade` 使用真实 0.1.5 旧载荷完成 0.1.5 → 0.1.9 升级、pg_dump 备份、失败续升级及配置/公钥/授权/课程保留；这是本机普通进程验证，不代表 Server 2025 上安装过不支持该系统的旧包。
