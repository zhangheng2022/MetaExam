# M3 第四批：本地诊断报告

本地管理器新增“故障诊断”折叠面板，提供检查诊断、导出诊断报告。普通权限可用，不需要软件激活。服务停止或数据库不可用时仍可导出部分报告；不可确认的字段明确返回 unknown／null，不推断为未初始化或未激活。

## 使用

1. 用当前源码执行 `tools/run.ps1 dev`，展开管理器中的“故障诊断”。
2. 点击“检查诊断”，核对考试服务、数据库就绪、系统状态、后台任务、版本和维护记录。检查结束同步刷新概览；报告是带时间的快照，不随自动轮询悄悄改变。
3. 点击“导出诊断报告”，通过原生对话框选择程序／数据目录外的新 `.json` 文件。导出重新采集当前状态；取消不采集、不写文件。已存在的文件拒绝覆盖，请换新名称。
4. 断连报告包含无法连接状态；503 与异常响应单独标注。存在升级／维护记录时只做提示，不删除记录、不执行恢复或启停服务。按相应升级／备份说明继续维护。

## 报告与边界

JSON format 1 只包含产品名、采集时间、管理器与运行时版本、平台／架构、三个固定回环接口的状态码、数据库／Worker／初始化／授权枚举、迁移版本及两类维护标记的存在状态。每项值经过枚举、布尔、整数范围或版本格式检查；未知响应属性直接舍弃。数据库不可用时身份与授权字段保持未知。

报告不包含原始日志、账号名单、题目答案、密码摘要、Cookie、管理令牌、授权原文、公钥、设备指纹、环境变量或路径。采集不读取原始日志和业务表；定位本机接口与维护目录时所需的配置只留在主进程。不是完整日志归档或系统服务故障根因分析器；接口不可连接不等于确认 Windows 服务已停止。报告也不证明独立环境已验收。导出写入本机，应用不上传报告。

主进程只请求固定 `127.0.0.1` 的 health/live、health/ready 和 system/status，不接受任意 URL，不发送 Cookie，不跟随重定向；每项超时 5 秒，响应体上限 16 KiB。维护记录只检查文件元信息，不读取内容；路径链接、权限或文件系统异常按无法确认处理。

preload 仅增加无参数的 `checkDiagnostics`、`exportDiagnostics`。IPC 复用主 frame／本地来源校验，拒绝额外参数；无任意 HTTP、文件和命令能力。只在主进程处理文件选择与保存，渲染层拿不到本机路径。保存使用排他创建，拒绝现存文件、UNC、链接目录、非 JSON 扩展名及程序／数据／配置目录。文件写入失败只返回固定错误码，不暴露底层错误文本。

## 验证与交付

`test:diagnostics` 覆盖脱敏、未知状态、恶意／超大响应、超时、非回环拒绝、链接与覆盖保护、并发及取消；真实 Electron 验证界面、原生选择器适配、文件内容、断连／503、外部窗口 IPC 拒绝和 380px 窄窗口。文件对话框在测试中被替换以避免人工选择，其余采集、IPC 和保存链路使用真实代码。`test:desktop` 另使用真实 API／独立数据库验证报告状态与原初始化功能。截图在忽略提交的 `artifacts/diagnostics`。

本批不改变数据库、安装器或依赖版本，交付源码与开发构建，未重建 EXE。上一批 0.1.1 升级 EXE 保持原样，不包含本批功能；不要覆盖原始升级包影响同 buildId 续升级。后续版本打包时再纳入本批，并回归安装版普通／提升权限下的文件读取、保存对话框、HTTPS 信任和 Windows DPI。既有 Windows 升级独立环境清单仍待验收。

组件查询使用锁定的 Ant Design 6.7.2 CLI；视觉语言沿用 [Ant Design](https://ant.design/design.md)，原生保存对话框依据 [Electron dialog 文档](https://www.electronjs.org/docs/latest/api/dialog)。
